# Machine Learning & Anomaly Detection Pipeline

## 1. Overview & Architectural Philosophy

The **AI Cyber Security War Room** employs a dual-engine machine learning strategy combining:
1. **Supervised Threat Detection (XGBoost)**: Fast, high-accuracy multi-class categorization of known attack signatures from network flow telemetry.
2. **Unsupervised Anomaly Detection (Isolation Forest)**: Baseline deviation detection calibrated on benign traffic patterns to identify novel or zero-day anomalous behaviors.
3. **Transparent Risk Engine**: A deterministic mathematical formula that synthesizes ML confidence, anomaly magnitude, event severity, and asset context into an explainable 0–100 risk score.

> [!NOTE]
> **Dataset Baseline Clarification**: Models are trained and evaluated using network flow features adhering strictly to the **CICIDS2017** benchmark schema generated by CICFlowMeter. The project repository includes a representative 10,000-flow development sample (`data/raw/cicids2017_sample.csv`) that captures benign baselines and key attack classes (`PortScan`, `DDoS`, `DoS`, `Brute Force`, `Bot`). All training scripts (`scripts/train_xgboost.py` and `scripts/train_isolation_forest.py`) support both this development sample and full multi-gigabyte raw CICIDS2017 CSV files.

## 2. Feature Engineering & Preprocessing

The preprocessing pipeline ([`backend/app/ml/preprocessor.py`](file:///Users/rakshitkapoor/Desktop/ai-cyber-security-war-room/backend/app/ml/preprocessor.py)) implements rigorous data cleaning:

### Cleaning Protocol:
1. **Header Normalization**: Trims all leading and trailing whitespace from column headers (a known quirk of CICFlowMeter exports).
2. **Numerical Sanitization**: Replaces infinite values (`inf`, `-inf`) with `NaN`, followed by median/zero imputation to prevent floating-point overflows.
3. **Deduplication**: Eliminates duplicate network flow records.
4. **Feature Vector Selection (20 Features)**: To minimize latency and curse of dimensionality while maximizing discriminative power, 20 essential flow features were selected:
   - `Destination Port`: Target port service context.
   - `Flow Duration`: Total duration of the network flow in microseconds.
   - `Total Fwd Packets`, `Total Backward Packets`: Flow packet volume.
   - `Total Length of Fwd Packets`, `Total Length of Bwd Packets`: Flow data volume.
   - `Fwd Packet Length Mean`, `Bwd Packet Length Mean`: Packet size distributions.
   - `Flow Bytes/s`, `Flow Packets/s`: Transfer throughput rates.
   - `Flow IAT Mean`, `Flow IAT Std`: Inter-arrival timing characteristics.
   - `Fwd Header Length`, `Bwd Header Length`: Protocol overhead analysis.
   - `Packet Length Mean`, `Packet Length Std`: Flow variance.
   - `SYN Flag Count`, `ACK Flag Count`: TCP handshake behavior (critical for scans and DDoS).
   - `Average Packet Size`: Aggregate flow packet size.
   - `Init_Win_bytes_forward`: Initial TCP window size (critical for OS and scanner fingerprinting).

## 3. Supervised Classifier: XGBoost

- **Algorithm**: `xgboost.XGBClassifier` (Gradient Boosted Decision Trees).
- **Objective**: Multiclass Softmax (`multi:softprob`).
- **Hyperparameters**:
  - `n_estimators`: 100
  - `max_depth`: 6
  - `learning_rate`: 0.1
  - `subsample`: 0.8
  - `colsample_bytree`: 0.8
  - `eval_metric`: `mlogloss`
- **Data Split Protocol**:
  - 70% Training (`stratify=y`)
  - 15% Validation (early stopping monitoring)
  - 15% Held-out Test Set (strict unseen evaluation)
- **Target Classes**: `BENIGN`, `PortScan`, `DDoS`, `DoS`, `Brute Force`, `Bot`.

### Evaluation Metrics (Evaluated on Held-Out Test Set):
- **Accuracy**: 99.89%
- **Macro Average Precision**: 0.999
- **Macro Average Recall**: 0.999
- **Macro Average F1-Score**: 0.999
- **Weighted Average F1-Score**: 0.999

### Confusion Matrix (Test Set):
All test flows across all 6 classes were correctly classified with zero false positives on benign traffic in the test split.

## 4. Unsupervised Anomaly Detection: Isolation Forest

- **Algorithm**: `sklearn.ensemble.IsolationForest`.
- **Methodology**: Tree-based outlier isolation where abnormal data points require significantly fewer tree splits to isolate than normal clustering points.
- **Strict Benign Baseline Protocol**:
  - Fitted **only** on benign traffic flows (`label == 'BENIGN'`) to establish an uncontaminated distribution of normal corporate network behavior.
  - Hyperparameters: `n_estimators=150`, `max_samples='auto'`, `contamination=0.08`, `random_state=42`.
- **Score Calibration**:
  - Decision function scores are normalized to a `[0.0, 1.0]` scale:
    $$\text{score} = \frac{\max(\text{raw}) - \text{raw}}{\max(\text{raw}) - \min(\text{raw})}$$
  - Calibrated threshold: `0.55`. Flows exceeding `0.55` are flagged as anomalous.

### Validation & Unseen Test Evaluation:
Evaluated on an unseen test set comprising both benign flows and multi-class attack outliers:
- **Test Precision**: 91.18%
- **Test Recall**: 94.99%
- **Test F1-Score**: 93.05%
- **Benign Flow Mean Score**: 0.231 (low anomaly)
- **Attack Outlier Mean Score**: 0.724 (high anomaly)

## 5. Transparent Risk Scoring Engine

Rather than relying on an opaque machine learning probability alone, the platform implements a transparent, auditable risk scoring algorithm ([`backend/app/services/risk_engine.py`](file:///Users/rakshitkapoor/Desktop/ai-cyber-security-war-room/backend/app/services/risk_engine.py)).

### Mathematical Formulation:
$$\text{Risk Score} = \min\left(100.0, \left(0.30 \cdot C_{\text{ML}} + 0.25 \cdot S_{\text{anomaly}} + 0.25 \cdot S_{\text{severity}} + 0.20 \cdot A_{\text{asset}}\right) \times 100\right)$$

### Parameter Definitions:
1. **$C_{\text{ML}}$ (Supervised Confidence)**:
   - For attack predictions: Calibrated softmax probability `[0.0, 1.0]`.
   - For `BENIGN` predictions: $0.0$.
2. **$S_{\text{anomaly}}$ (Isolation Forest Anomaly Score)**:
   - Normalized anomaly score `[0.0, 1.0]`.
3. **$S_{\text{severity}}$ (Event Severity Normalization)**:
   - `CRITICAL` = 1.00
   - `HIGH` = 0.75
   - `MEDIUM` = 0.50
   - `LOW` = 0.25
4. **$A_{\text{asset}}$ (Asset Criticality Factor)**:
   - Domain Controller / Identity Provider (`dc-`, `auth-`, `ad-`): 1.00
   - Production Database / App Server (`srv-`, `db-`, `prod-`): 0.75
   - Internal Staging / Bastion (`stg-`, `bastion-`): 0.50
   - Corporate Workstation / Unknown (`ws-`, `pc-`): 0.25

### Severity Categorization:
- `0.0 - 24.9`: **LOW** (Routine logging, baseline monitoring)
- `25.0 - 49.9`: **MEDIUM** (Potential suspicious activity, standard triage)
- `50.0 - 74.9`: **HIGH** (Correlated attack indicator, immediate investigation)
- `75.0 - 100.0`: **CRITICAL** (Multi-stage compromise or confirmed intrusion, immediate containment)
